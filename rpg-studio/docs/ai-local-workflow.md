# Codex / Claude Codeでローカル制作

この工房はAI APIを内蔵しません。プロジェクト一式をPCに展開し、そのフォルダーをCodexまたはClaude Codeの作業フォルダーとして開いて、AIにJSON・画像・スクリプトなどの実ファイルを読ませて制作します。モデルへの送信やデータの取り扱いは利用するAIサービスとアカウントの設定に従います。

## 使い始める

1. `rpg-studio` のZIPをPC上の作業フォルダーへ展開します。
2. Codex Desktopで展開先フォルダーをプロジェクトとして開くか、そのフォルダーからCodex CLIを起動します。Claude Codeも同じフォルダーを作業ディレクトリにして起動します。
3. Codexはルートの `AGENTS.md`、Claude Codeは `CLAUDE.md` から共通の `AGENTS.md` を参照します。対象プロジェクトに `IDEA.md` がある場合は、今回の依頼と関係する内容を読みます。これは任意の発想メモで、ない場合に作成する必要はありません。`README.md` があれば概要を確認します。Node.js 22以上とpnpm 10.18.0を用意して `pnpm install` を実行すると、検証・試遊・ビルド用のCLIも使えます。
4. 技術的な土台が必要なら、RPGには `pnpm rpg new <id> --title "<作品名>"`、独立作品には `pnpm rpg new <id> --type experience` を使えます。状態遷移型はTypeScript、独自構成は `--runtime static` を選びます。後者は `index.html` 起点のHTML/CSS/JavaScript/WASM等をそのまま使います。`IDEA.md` は任意です。すでにプロジェクトや試作品、制作資料がある場合は、作り直したり決まったファイルへ移したりせず、そのまま対象にします。
5. スキルを直接呼び出すか、普通の言葉で作りたい内容を頼みます。

```text
Codex:       $rpg-studio projects/<あなたの作品ID> の既存ファイルを読み、作り手が指定した制作段階と今回の着手点から、頼まれた範囲を進めてください。新規プロジェクトが必要な場合だけ技術的な土台を作ってください。
Claude Code: /rpg-studio projects/<あなたの作品ID> の既存ファイルを読み、作り手が指定した制作段階と今回の着手点から、頼まれた範囲を進めてください。新規プロジェクトが必要な場合だけ技術的な土台を作ってください。
```

作り手の制作段階とプレイヤーがゲーム内で最初に出会う場面は別々に扱います。作業の順序・大きさ・使う資料・AIとの相談頻度も作り手の希望に合わせ、方法を混ぜたり途中で変えたりできます。プロローグ・チュートリアル・最小の遊べる形・作業カード・仕様書などを一律に求めず、設定・プロット・台本・途中の場面・試作品・既存プロジェクトの続きなど、指定された入口から始めます。

`<あなたの作品ID>` は作業するプロジェクトIDに置き換えます。スキル名を指定しなくても、依頼内容に合えばAIが選ぶことがあります。Claude Codeでは `/skills` で利用できるスキルを確認できます。Codexはスキルの場所と `SKILL.md` にある説明をもとに必要なときに読み込みます。

## スキルの置き場所

このプロジェクトには両ツール向けの同じ `rpg-studio` スキルを同梱しています。

| ツール | プロジェクト内の場所 | 呼び出し |
| --- | --- | --- |
| Codex | `.agents/skills/rpg-studio/SKILL.md` | `$rpg-studio` |
| Claude Code | `.claude/skills/rpg-studio/SKILL.md` | `/rpg-studio` |

スキルの本文はプレーンテキストのMarkdownです。内容を確認・編集したいときは、両方の `SKILL.md` を同じ内容に保ってください。共通の制作規約はルートの `AGENTS.md` に置き、Claude Code用の入口 `CLAUDE.md` もそこへ案内します。

## AIへの頼み方

- 何を作るか、対象プロジェクト、プレイヤーがどう操作し何が起きるかを伝えます。細かい実装方法が決まっていなくても、遊びの意図を説明すれば既存データを調べて実装案を作れます。
- 白紙から始める必要はありません。すでにある設定・初期プロット・台本・特定の場面・試作品や既存プロジェクトを読み、作り手が指定した地点から続けます。物語上の冒頭は、別に指定されない限り作りません。
- 作り方の希望（例は一部です）も `IDEA.md` やその場の依頼に書けます。作業カード・先に仕様を書く・小さく試す・一度にまとめて作るなどの選択は作り手に任せ、例にない方法や途中での変更にも合わせます。
- 作品の核となる発想を `projects/<id>/IDEA.md` に残すと、別の会話でも作り手の意図を参照できます。既存の資料を使う、依頼ごとに伝える、文書を作らず進める方法も選べます。
- 画像・音・フォントは希望する雰囲気や用途を伝えます。第三者素材の取得元や利用条件を確認し、候補を選ぶ段階は利用者が行います。
- 「実装だけ」「まず案を見せて」「検証まで」など、今回どこまで進めるかも指定できます。

## ローカル環境での確認

```sh
pnpm rpg validate --project projects/<id>
pnpm rpg test --project projects/<id>
pnpm rpg build --project projects/<id>
```

独立作品は `validate` / `build` と `pnpm rpg dev --project projects/<id>` に対応します。状態遷移型は `tests/*.experience.json` を `pnpm rpg test` で実行できます。静的サイト型は完成済みファイルをそのまま配信できます。ソースビルドは `experience.json` に手順と成果物フォルダーを指定し、内容を確認したうえで `pnpm rpg build --project projects/<id> --run-project-build` を明示して実行します。通常の `validate` / `test` / `dev` やブラウザ工房は設定コマンドを実行しません。任意のゲームロジックには作品独自のテスト方法を使います。

AIには必要な作業範囲のコマンドを依頼できます。変更したファイルと実行したコマンドの結果を確認し、ユーザーの意図どおりかを見てから配布してください。AIがファイルを変更できる範囲は、CodexまたはClaude Code側でこのフォルダーに設定したアクセス権に従います。
