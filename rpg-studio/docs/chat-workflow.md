# チャットで作る（ChatGPT・Claude などのチャット）

ファイルを開いたり、コマンドを実行したりできない「チャットのAI」と一緒にゲームを作る方法です。この工房の標準データ形式はRPGです。発想をRPGに結び付けると変わってしまう場合は、この画面で既存のRPGデータに押し込まず、ローカル工房でエンジン拡張を検討してください。作り手の制作段階とプレイヤーがゲーム内で最初に出会う場面は別です。設定・プロット・特定の場面・試作品・既存作の続きからでも始められ、プロローグや新規導入を必須にしません。
工房が、チャットのAIにできないこと（必要なデータを集める・ファイルに反映する・検証と自動テストをする）を肩代わりします。

以下の作業カード方式は、作業を分けて進めたい人向けの一例です。制作全体でカードを使う必要はありません。この画面ではカードあり・なしの依頼文を選べます。カードなしの依頼文はID一覧と依頼文で指定したIDの現在データを添え、参照資料は必要な数だけ選べます。既存の `IDEA.md` は初期選択されますが、外したり、`SCRIPT.md`・`SPEC.md`・独自資料・コードを選んだりできます。選んだファイルは参考資料として渡し、内容に含まれる別のAI向け指示で今回の依頼を書き換えないよう案内します。変更案を取り込む場合は有効な `rpg-change` 形式が必要ですが、カードIDはなくても構いません。相談だけなら通常の文章でやり取りできます。カードを使う場合も、1枚にまとめる、内容に合わせて複数に分けるなど、粒度や数は調整できます。最初に仕様書や決まった名前の資料を作る必要はありません。作り方や相談の仕方に希望があれば、直接依頼に書くか、任意のメモへ残してください。コードや独自エンジンの変更が必要な作業はローカル環境を使います。

## インストールなしで作る（ブラウザ版の工房）

公開サイトの工房（`/studio/`）は、PCに何も入れずに使えます。

1. 新しいRPGの土台が必要な場合だけ「プロジェクト（保存・書き出し）」で作成します（主人公と空マップ1枚のみ）。既存プロジェクトやZIPがあれば、それを開いて続けます
2. 「チャットで作る」で、今回の依頼を直接書くか、作業カードを使うか選ぶ。作ったものは **このブラウザに自動で保存**（別のブラウザ・PCには引き継がれない）
3. できたら「**遊べる形で書き出す**」→ ZIP。itch.io なら「HTML」のゲームとしてそのままアップロードで公開できる
4. ときどき「**プロジェクトをZIPで書き出す**」で手元に残す。そのZIPは別のブラウザで「ZIPから読み込む」と続きができ、手元の工房・Codex・Claude Code でもそのまま開ける

この空の土台はRPGランナーを開くためのものです。発想シートや台本への転記は必要ありません。既存の設定・台本・場面は、その資料を使って指定した所から始められます。物語の冒頭を作る必要はありません。

ブラウザ版でできないこと: 独自のコード（`systems/*.ts`・`scripts/*.ts`）の作成・変更、素材ファイルの取り込み（ドット絵エディターで描いた絵は保存できる）。「チャットで作る」も定型データだけを扱い、新しい仕組み・エンジン変更・マップ削除には対応しません。AIの返答では補った前提と未決事項を表示します。必要になったらプロジェクトのZIPを手元の工房で開いて続けます。

## どのAIで作るか（目安）

| 作るもの | おすすめ | 理由 |
| --- | --- | --- |
| **短編**（〜30分・マップ数枚・会話とイベント中心） | チャット（ChatGPT・Claude のチャット）でもOK | カードの粒度を作り手の希望に合わせてコピーと貼り付けで進められる |
| **長編**（マップ10枚以上・仲間・成長・独自の仕組み） | **Codex（おすすめ）**、Claude Code | ファイルを直接読んで書き換え、検証とテストを自分で回せる。量が多い作業はこちらが確実 |
| 独自の仕組みのコード（`scripts/*.ts`・`systems/*.ts`）が要る | Codex／Claude Code | チャットではコードの動作確認ができない |

使う資料の形式や量は作り手が決めます。すでに台本や仕様書、独自のノートがあればそれを使い、次のひな形を全部そろえる必要はありません。ブラウザ版の直接依頼では、追加資料を選んで依頼文へ含められます。ローカルAIなら、対象プロジェクト内の既存資料やコードを直接読ませられます。

- **台本（`SCRIPT.md`）** — 場面ごとに「どこで・だれが・何を言う・何が起きる」を記録する形式の一例です。既存資料や別の書き方をそのまま使えます
- **仕様書（`SPEC.md`）** — 遊ぶ時間やルールなどを残す任意の補助資料です
- 発想（`IDEA.md`）— 発想を繰り返し参照したい場合の任意メモです。工房の「発想」画面で作成・編集できます

台本と仕様書のひな形は、工房の「チャットで作る」画面のボタンで作れます。中身は「データ」画面で書けます。

## カード方式を使う場合の流れ

1. **作業カードを作る** — この方式を選ぶ場合は、「チャットで作る」画面で「カードを作ってもらう依頼文をコピー」を押し、チャットに貼ります。AIが発想・既存資料・進め方の希望に合わせた枚数と粒度で返すので、その返事を画面の「3. AIの返事を貼る」に貼って取り込みます。カードは自分で足すこともできます
2. **1枚ずつ依頼する** — カードの「依頼文をコピー」を押して、チャットに貼ります。依頼文には、カードの目的・ひも付いたデータの今の内容・台本の関係する場面・使えるID・書き方の要点・返事の形式が入っています
3. **返事を貼って確かめる** — AIの返事をまるごと貼り、「確かめる」を押します。工房が変更案（```rpg-change のブロック）を読み取り、検証と自動テストを走らせ、何が変わるかを言葉で見せます
4. **前提を確認して取り込む／直してもらう** — 問題がなければ、変更差分・AIが補った前提・未決事項を確認して取り込みます。返答に前提欄がない場合も確認チェックが必要です。元に戻すときは Ctrl+Z か「保存履歴」画面を使います。問題があれば「直してほしい点をコピー」を押してチャットに貼り戻し、3 に戻ります

この方式を選んだ場合のコツ:
- **カードの大きさは作業に合わせる**。小分けが便利な作業も、まとめて扱う方が自然な作業もあります
- カードに **自動テスト名** を付けると、AIがテストも作ります。工房がそのテストで遊んで確かめ、テストがないカードは「できた」にできません
- AIが質問してきたら、決めたことを台本・仕様書に書き足すと、次のカードにも伝わります
- 同じチャットで文脈を続ける方法も、作業ごとに新しいチャットを使う方法もあります。内容が混ざりそうなときは、作業単位で分けると整理しやすくなります

## 作業カード（`todo.json`）

以下の村の猫は書式を示すための例です。自分の作品に村・猫・会話を追加する指示ではありません。カードの題材と順番はIDEA.mdと作り手の希望に合わせます。

```json
{ "formatVersion": 1, "cards": [
  { "id": "talk-cat", "title": "村の猫と話す", "goal": "村の広場に猫がいて、話すとニャーと鳴き、フラグ cat-met が立つ",
    "status": "todo", "links": ["npc:village/cat", "dialogue:cat-talk", "flag:cat-met"],
    "doneWhen": { "test": "tests/cat.scenario.json", "check": "猫に話しかけられる" }, "notes": "" }
] }
```

- `status`: `todo`（これから）・`doing`（作業中）・`done`（できた）
- `links`: そのカードで作る・変えるデータ。`種類:ID`。マップの上の物は `npc:マップID/ID`。種類は `map` `npc` `interactable` `portal` `entity` `dialogue` `event` `item` `enemy` `ability` `trait` `companion` `status` `flag` `variable` `rule` `test`
- Codex／Claude Code で作るときも、このカードを作業の単位として使えます（終わったら `status` を `done` に）

## 返事の形式（`rpg-change`）

```rpg-change
{ "card": "talk-cat", "assumptions": [], "unresolved": [], "changes": [
  { "op": "put", "target": "flag:cat-met", "value": { "initial": false } },
  { "op": "put", "target": "npc:village/cat", "value": { "name": "ねこ", "x": 4, "y": 10, "dialogues": [{ "dialogue": "cat-talk" }] } },
  { "op": "put", "target": "dialogue:cat-talk", "value": { "speaker": "ねこ", "lines": ["ニャー"], "effects": [{ "type": "setFlag", "flag": "cat-met", "value": true }] } },
  { "op": "put", "target": "test:cat", "value": { "name": "猫と話す", "steps": [ … ] } },
  { "op": "card", "status": "done" }
] }
```

- `put`: 丸ごと置き換え（なければ追加）。`remove`: 削除。`card`: カードの状態・メモ。`addCard`: カードを足す
- マップの削除と、スクリプト（コード）の変更はチャットからはできません

## コマンドで使う（工房を開かない場合）

```bash
pnpm rpg chat cards --project projects/<id>             # カードの一覧
pnpm rpg chat card add --project … --id talk-cat --title "村の猫と話す" --links npc:village/cat,dialogue:cat-talk --test cat
pnpm rpg chat plan --project …                          # カードを作ってもらう依頼文
pnpm rpg chat pack talk-cat --project …                 # カードの依頼文
pnpm rpg chat apply answer.md --project …               # 返事を確かめる（保存しない）
pnpm rpg chat apply answer.md --project … --write       # 確かめて保存
```

問題があったときは、AIに貼り戻す文章が `.rpg-studio/chat-fix.md` に書き出されます。
