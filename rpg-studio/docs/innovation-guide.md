# 革新的な仕組みをAIで作る

> 発想を受け取ったら、まず [idea-to-game.md](idea-to-game.md)（発想を削らない進め方と、発想→部品の対応表）を読んでください。

このエンジンの狙いは「RPGツクールの代わり」ではありません。**作り手とAIが、まだ誰も作っていない遊びを発明できること**です。そのために、仕組みを4つの層に分けています。AIは必要な層まで降りていけます。

| 層 | 何を書くか | できること |
| --- | --- | --- |
| ① データ | JSON（マップ・会話・イベント・特性・ルール・式） | 大半のゲームはここだけで作れる。[customization-guide.md](customization-guide.md) |
| ② 世界の仕組み | エンティティ・領域・調べるタイル・時限イベント・集合・周回・戦闘式 | 生きた世界、知識で開く探索、時間制限、ループもの |
| ③ 拡張（TypeScript） | `defineSystem` の条件・関数・アクション・**独自画面**・**描画レイヤー**・HUD・歩行やtickのフック | 新しい画面と遊び（パズル、カード戦闘、ミニゲーム、天候、視界）。[extension-api.md](extension-api.md) |
| ③' ジャンルモジュール | `project.json` の `modules` で有効にして、データから呼ぶ（26種。アクション・格闘・防衛・落ちもの・3Dダンジョンなども） | RPGの中に他ジャンルの遊びを織り込む。[genre-modules.md](genre-modules.md) |
| ④ エンジン改造 | `packages/engine`・`runtime`・`schema` | 上でも足りない根本的な仕組み（形式とテストを一緒に更新する） |

## ② 世界の仕組み（データだけで使える）

| 部品 | 内容 |
| --- | --- |
| **エンティティ** `maps/*.json › entities` | 人・物・怪物。`states` を上から評価して、条件を満たす最初の状態が有効になる（見た目・会話・イベント・通れるか・発動方法・動き方が状態ごとに変わる）。どの状態も満たさなければ消える。発動方法は `action`（調べる）/ `touch`（触れる・追いつかれる）/ `auto`（その状態になった瞬間に1回）/ `none` |
| **動き方** `behavior` | `still` / `wander`（半径内を徘徊）/ `patrol`（経路を巡回）/ `chase`（範囲内なら追跡）/ `flee`（逃げる）。世界は「tick」（約0.33秒ごと）で進む |
| **調べるタイル** `tiles.json › inspect` | そのタイルを向いて調べると実行される。`when` を満たさなければ `otherwise` が実行されるので、「古代文字を覚えるまで読めない石板」のような仕掛けが作れる |
| **領域** `maps/*.json › regions` | 範囲に入る・出る・中を歩く・中で調べる時の効果。条件 `{"inRegion": id}` でも参照できる（暗い洞窟、毒の沼、聖域、店の中など） |
| **時限イベント** `schedule` / `cancelSchedule` | N歩後に効果を実行する（制限時間、遅れて届く手紙、呪いの進行） |
| **集合** `project.json › sets` | 文字列の集まり（知識、合言葉、出会った人、集めた記憶など）。`addToSet` / `removeFromSet`、条件 `{"set": "clues", "has": "x"}`、式 `{"size": "clues"}`、文中の `{{set.clues}}`。`show: true` にするとメニューに手帳として出る |
| **周回と記憶** `persist: "meta"` | `meta` 指定のフラグ・変数・集合は、`newCycle` やゲームの再開をまたいで残る。式 `{"cycle": true}` で何周目かがわかる |
| **エンディング** `project.json › endings` + `ending` 効果 | エンディング画面を出し、組み込みの meta 集合 `endings` に記録する。画面を閉じると、記憶を持ったまま次の周回が始まる |
| **戦闘のルール** `project.json › battle` | `playerDamage` / `enemyDamage` / `fleeChance` を式で差し替える（ctx: attack, defense, power, variance）。`commands` で、たたかう・ぼうぎょ・わざ・どうぐ・にげる を個別にON/OFF |
| **エンティティの移動** `moveEntity` | 演出（人物を動かす、扉の前からどかす） |

## ③ 拡張（TypeScript）でできること

| フック | 用途の例 |
| --- | --- |
| `conditions` / `functions` | データから `{"custom": "id.name"}` / `{"fn": "id.name"}` で呼ぶ判定・計算（距離、時間帯、運勢、相性表など） |
| `actions` | データから `{"type": "system", ...}` で呼ぶ処理。たくさんの効果を返せる（手続き型ダンジョンなら `setTile` を大量に返す） |
| `scenes` | **独自の画面**。`start` / `input` は純粋関数（テストで動く）、`render` はブラウザで描く。パズル、カード戦闘、リズム、料理、地図、推理ボード… |
| `drawOverlay` | マップの上に描く。暗闇と灯り、天候、霧、視界、熱源の可視化 |
| `hud` | 画面上部に情報を追加する |
| `onStep` / `onTick` | 歩くたび・時間が進むたびの処理（空腹、体温、匂いの追跡、昼夜） |
| `modifyDamage` / `onLethalDamage` / `canPass` / `onBattleStart` | 戦闘と移動の細かな割り込み |

サンプルにある実例:
- `systems/rune-lock.ts`: 独自画面（3つのダイヤルを回す暗号錠）
- `systems/lantern.ts`: 描画レイヤー（遺跡の暗闇と灯り）とHUD
- `systems/chronicle.ts`: アクション（旅の記録を集計して文章にする）

## 発想のカタログ

部品を組み合わせると、ツクール的なRPGの外側にある遊びが作れます。

| 発想 | 組み立て方 |
| --- | --- |
| **時間ループ探偵**（同じ1日を繰り返して真相に迫る） | 時限イベントで1日の出来事を進める → 最後に `ending` か `newCycle`。手がかりは meta 集合に残す。NPCは周回数と記憶で台詞や行動（状態）を変える |
| **知識で開く世界**（鍵は物ではなく「知っていること」） | 集合 `knowledge` を手に入れるのは会話・石板・本。扉・タイル・会話の選択肢を `{"set":"knowledge","has":...}` で開く。周回しても知識だけは残す（meta） |
| **潜入・ステルス** | 衛兵を `patrol` で巡回させ、範囲に入ると `chase` に切り替わる状態を作る。見つかる＝触れられると捕まる。影の領域では状態が切り替わらないよう条件をつける。視界は `drawOverlay` で描く |
| **侵食する呪い** | 時限イベントと `setTile` で、時間がたつほど地形が変わる。浄化したマスは meta に記録 |
| **言葉で戦う**（語彙がそのまま技になる） | 集めた単語（集合）を `choice` の選択肢に並べ、組み合わせで相手の変数（心の距離）を動かす |
| **死に戻り** | `defeat` ルールで記憶を増やして `newCycle`。死ぬたびに知識が増える |
| **カード／リズム／パズル戦闘** | シンボルエンカウント（`touch` のエンティティ）から `startScene` で独自画面を開き、勝敗をフラグや変数で返す。組み込みの戦闘は使わなくてよい |
| **生活と人間関係** | NPCごとの好感度変数、時刻変数（`onTick`）、時刻で状態が変わるエンティティ（朝は店、夜は酒場）。週の終わりに評価の `ending` |
| **ローグライク** | システムのアクションで乱数から部屋を掘る（`setTile` を返す）。死んでも meta の通貨で恒久強化 |
| **物理パズル**（倉庫番風） | `onStep` で、押した方向に岩エンティティを `moveEntity` し、全部が目標の領域に入れば扉を開ける |
| **天候と生態系** | `onTick` で天気変数を変え、`drawOverlay` で雨を描く。雨の日だけ出る生き物（状態）、雨で通れなくなる川（`passableWhen`） |

## AIへの頼み方

工房の「検証」画面にある依頼文ボタンか、次の文例を使ってください。

> まだ誰も作っていないRPGの仕組みを一緒に発明したい。テーマは「〇〇」。
> 1. docs/innovation-guide.md と `pnpm rpg catalog` を読み、データだけで作る案、拡張（systems/*.ts）を使う案、エンジン改造が必要な案を、遊びの面白さと作業量つきで3つ提案して。
> 2. 私が選んだ案を、まずデータで作れる部分から実装し、足りない部分だけを defineSystem（scenes / drawOverlay / conditions …）で書いて。
> 3. 仕組みごとに tests/*.scenario.json を書き、`pnpm rpg validate` / `test` / `build` を通して。

## 守ってほしいこと（自由にするための約束）

- **決定性**: ゲームの処理（`input`・`conditions`・`actions`・`onStep`・`onTick`）では `Math.random()` や現在時刻を使わない。乱数はデータの `random` / `chance` 効果、または状態から計算する。こうしておけば、セーブ・ロード・テスト・リプレイが壊れない（描画の `render` / `drawOverlay` は自由）。
- **状態はJSON**: 独自画面の `data` や `systemData` には、JSONにできる値だけを入れる（セーブされるため）。
- **データを主役に**: TypeScriptには「仕組み」を書き、具体的な数値・文章・配置はJSONに出す。こうすると、作り手が工房で調整できる。
- **テストを書く**: 新しい仕組みには、シナリオ（`tick`・`sceneInput`・`expect` の `sets` / `entities` / `cycle` など）で動作確認を付ける。
